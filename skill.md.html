1. Gerenciamento de Ambiente e Dependências — Poetry

O Poetry é a ferramenta oficial e obrigatória para gerenciamento de dependências, controle de empacotamento e isolamento de ambientes virtuais (.venv).

⛔ Proibição Estrita

O uso direto de pip install, pip uninstall ou pip freeze é estritamente proibido em qualquer etapa do ciclo de vida do projeto.

📌 Razão Técnica

O Poetry garante ambientes reproduzíveis e determinísticos através da resolução de dependências no poetry.lock e separação estrita de ambientes de produção e desenvolvimento.

1.1 Configuração da Virtualenv no Projeto

O diretório virtual deve sempre residir dentro da pasta raiz do repositório:

bash
poetry config virtualenvs.in-project true --local

1.2 Comandos Operacionais Essenciais

bash
# Instalação limpa com base no poetry.lock
poetry install --no-root

# Adicionar dependência de produção
poetry add pandas pydantic pydantic-settings requests

# Adicionar dependências exclusivas de desenvolvimento
poetry add --group dev ruff pytest pytest-cov mkdocs mkdocs-material mkdocstrings[python]

# Executar ferramentas no contexto da virtualenv
poetry run ruff check .
poetry run pytest

2. Arquitetura Modular e Organização do Projeto

Todo projeto adota o padrão de layout com pasta src/, garantindo separação limpa entre o código-fonte importável, testes e artefatos de documentação.

projeto/ ├── src/ │ └── projeto/ │ ├── __init__.py │ ├── main.py # Ponto de entrada CLI (sem lógica de negócio) │ ├── config/ # Variáveis de ambiente validadas │ ├── models/ # Schemas Pydantic / Dataclasses tipadas │ ├── extractors/ # Conectores com APIs, bancos e mensageria │ ├── transformers/ # Funções puras e regras de negócio │ ├── loaders/ # Carga idempotente em Lake / DW │ ├── pipelines/ # Orquestração do ciclo ETL / ELT │ ├── services/ # Clientes e conexões externas │ └── utils/ # Utilitários transversais e logs estruturados ├── tests/ │ ├── conftest.py # Fixtures compartilhadas │ ├── unit/ # Testes unitários isolados com mocks │ └── integration/ # Testes de integração ├── docs/ # Documentação MkDocs ├── .github/workflows/ci.yml # Pipeline de automação de CI ├── .env.example # Modelo público de variáveis ├── pyproject.toml # Manifesto único de dependências e ferramentas ├── mkdocs.yml # Configuração da documentação └── SKILL.md # Guia canônico de governança
💡 Importações Absolutas

Sempre utilize importações absolutas referenciando o pacote projeto (ex: from projeto.transformers.cleaner import normalize_payload). Nunca utilize caminhos relativos com ...

3. Padronização de Código com Ruff

O Ruff é a única ferramenta autorizada de linting, formatação e organização de imports, substituindo Flake8, Black e isort.

Conceito Comando Finalidade
Linting poetry run ruff check . Detecta erros, variáveis não usadas e anti-padrões.
Autofix poetry run ruff check . --fix Aplica correções automáticas e organiza imports (isort).
Formatação poetry run ruff format . Aplica estilo visual consistente e quebra de linhas.
Validação CI poetry run ruff format --check . Garante que o código no repositório já está formatado.

4. Testes Unitários com Pytest

A confiabilidade e estabilidade dos pipelines é garantida por testes unitários independentes e automatizados.

⚠️ Cobertura Mínima Obrigatória

O pipeline de CI falha automaticamente caso a cobertura total de testes fique abaixo de 50% (--cov-fail-under=50). A meta recomendada para módulos críticos de negócio é de 80%+.

  • Isolamento Absoluto: Testes unitários jamais realizam chamadas reais para a internet, nuvem ou bancos de dados. Utilize unittest.mock.
  • Padrão AAA: Organize os testes nas seções claras de Arrange (preparação), Act (execução) e Assert (validação).
  • Parametrização: Valide múltiplos cenários com @pytest.mark.parametrize.

5. Boas Práticas de Engenharia de Dados

  • Idempotência: O reprocessamento de qualquer período deve sobrescrever as partições correspondentes sem duplicar registros no destino.
  • Logs Estruturados: O uso de print() em produção é terminantemente proibido. Utilize o módulo logging.
  • Consultas Parametrizadas: Nunca monte queries SQL concatenando strings (evita vulnerabilidade de SQL Injection).
  • Timezone UTC: Todos os timestamps devem ser manipulados e persistidos em UTC explícito (timezone.utc).
  • Resiliência de Rede: Todas as chamadas HTTP ou de sockets externos devem possuir timeout e política de retentativa com recuo exponencial.

6. Regras de Comportamento para Agentes de IA

🤖 Diretrizes Imperativas para LLMs
  1. Inspecione a estrutura modular antes de sugerir ou editar arquivos.
  2. Use exclusivamente poetry run e poetry add (nunca pip install).
  3. Crie ou atualize os testes unitários para qualquer alteração de lógica.
  4. Garanta que as verificações de lint e formatação do Ruff sejam respeitadas.
  5. Nunca comite ou exiba credenciais literais no código.
  6. Nunca afirme que testes passaram sem tê-los executado de fato no terminal.

7. Critérios Obrigatórios de Entrega (Definition of Done)

  • ✓ A arquitetura modular em src/projeto/ foi rigorosamente seguida.
  • ✓ Todas as dependências novas foram gerenciadas exclusivamente via Poetry.
  • ✓ O linter do Ruff passou sem nenhum erro (poetry run ruff check .).
  • ✓ A verificação de formatação passou (poetry run ruff format --check .).
  • ✓ Todos os testes unitários foram aprovados (poetry run pytest).
  • ✓ A cobertura de código do pacote atingiu no mínimo 50%.
  • ✓ A documentação do MkDocs compila sem avisos críticos (poetry run mkdocs build).
  • ✓ Nenhuma credencial ou segredo foi exposto em commits ou logs.
